# Interview speech and evaluation changes

Speech uses en-IN with en-US fallback on unsupported language errors. Indexed final/interim results prevent duplicate final events, retain pending speech on end, and preserve answers across automatic restarts. Submission waits for recognition to finish. Unsupported browsers can type answers.

The evaluator sends raw and conservatively normalized transcripts plus verbatim code, uses an explicit partial-credit rubric, validates four scores, and computes overall = technical * 0.4 + coding * 0.2 + communication * 0.2 + problem solving * 0.2. Question context determines what evidence each dimension assesses. JSON extraction and trailing-comma repair are interview-specific; malformed evaluation responses receive a bounded retry. If Gemini remains unavailable or malformed, a deterministic evidence matcher issues a clearly labelled provisional score using question/rubric concepts and typo-tolerant term matching; blank answers remain skipped at zero. It does not use answer length as a score and does not label fallback results AI-verified. Saved provisional answers can be retried by an authorized company user.

The final percentage is calculated from persisted question marks (earned marks divided by available marks). A final summary failure does not block report creation: the backend uses saved answer feedback and computed scores. Company and mock interview reports persist question-wise answers, marks, evaluation source/status, totals, and fallback identifiers; the company report view and PDF surface those same totals and per-question details. Session completion can be restored from the backend after a page refresh.

MongoDB schemas retain transcripts, confidence (null when absent), statuses, four dimensions, overall, feedback, strengths and improvements. Candidate reports and PDF output include coding and distinguish outages from skips.
